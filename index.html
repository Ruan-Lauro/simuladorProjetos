TUTORIAL · PRIMEIROS PASSOS

Como conduzir o projeto

Você não está aqui para escolher respostas perfeitas. Está aqui para entender o cenário, tomar decisões justificadas e aprender com as consequências.

Seu papel

Você assume a responsabilidade de gerenciar um projeto de software.

Seu papel é priorizar entregas, coordenar a equipe, negociar com stakeholders, administrar riscos e tomar decisões com recursos limitados. O objetivo não é programar nem manter todos os indicadores no máximo.

Como uma tarefa chega a Done

Backlog → To Do → Doing → Review → QA → Done

Backlog: não iniciado. To Do: pronto para começar. Doing: implementação. Review: revisão da implementação. QA: testes e validações. Done: entrega técnica concluída e contabilizada.

Remaining 0 significa que a implementação terminou. A tarefa ainda pode precisar passar por Review e QA antes de chegar a Done.

O progresso geral recebe os pontos completos da tarefa somente quando ela chega a Done.

Roteiro recomendado para a semana

  1. Observe os indicadores e o Kanban.
  2. Resolva pendências críticas.
  3. Descubra por que tarefas importantes estão paradas.
  4. Elimine bloqueios antes de oferecer ajuda.
  5. Use ações de aceleração somente em tarefas executáveis.
  6. Encerre a semana.
  7. Confira o Histórico para entender o resultado.

Não é obrigatório gastar todas as ações de gestão.

Dúvidas explicadas sem excesso de informação

Estimate e Remaining

Estimate é o tamanho total da tarefa. Remaining é quanto ainda falta. O Estimate fica fixo e o Remaining diminui. Se Review ou QA pedir ajustes, a tarefa pode voltar para Doing com trabalho restante.

Estimate: 8 · Remaining: 8 → nenhum trabalho foi executado.
Remaining: 3 → ainda faltam 3 pontos.
Remaining: 0 → a implementação terminou.
Done → os 8 pontos entram no progresso.

Selecionar um item aumenta o escopo

O esforço do item de Backlog vira o Estimate da tarefa criada e entra no total usado para calcular o progresso. Os marcos podem já possuir tarefas vinculadas; selecionar outro item é uma decisão de expansão de escopo.

Antes: 20/37 = 54%.
Selecionar um item de esforço 5.
Depois: 20/42 = 48%.

Priorizar ou mudar a posição de um item não executa trabalho. Selecionar um item cria trabalho.

Por que uma tarefa não está avançando?

Verifique: blocker, dependência ainda não concluída, item adiado, espera por Review ou QA, trabalho restante do responsável e pendências críticas da semana.

Perguntar pode revelar um impedimento, mas não necessariamente o resolve. Conforme o caso, use ações como Escalar dependência ou Cobrar atualização do quadro. Nenhuma ação resolve todos os tipos de problema.

Quando Review ou QA pede ajustes

Doing → Review → ajustes solicitados → Doing com retrabalho → nova Review.

QA → falha encontrada → Doing com retrabalho → Review e QA novamente.

Se a tarefa voltou para Doing, não é necessário reabri-la manualmente. Confira Remaining, blocker e dependências. Uma reprovação não significa que o projeto travou definitivamente.

Quando usar Pair Programming e Oferecer ajuda

Pair Programming: use em uma tarefa complexa que esteja em Doing, sem blocker, com dependências concluídas e trabalho restante.

Oferecer ajuda: use em uma tarefa em To Do ou Doing, sem blocker, com dependências concluídas e trabalho disponível.

Ajuda não resolve blocker. Primeiro elimine o impedimento; depois acelere. Evite Pair Programming quando Remaining for 0 ou quando restar apenas um ajuste pequeno.

Aceite do stakeholder e progresso são coisas diferentes

Solicite aceite para tarefas que chegaram a Done. O aceite não acrescenta pontos ao progresso técnico. Esclarecimentos ajudam a alinhar expectativas.

Uma divergência de stakeholder não deve reabrir automaticamente uma entrega. Reabrir precisa ser uma decisão explícita; também pode ser adequado manter a entrega e negociar o alinhamento.

Não reabra automaticamente uma entrega apenas porque um stakeholder pediu esclarecimento.

Chegar a 90% ainda não encerra o projeto

A liberação pode exigir que não existam tarefas críticas bloqueadas, que o QA importante esteja concluído quando necessário, que exista satisfação mínima, documentação mínima e uma decisão final de release.

90% ou mais → preparar entrega → verificar condições → registrar documentação → decidir release → projeto concluído.

Exemplo: tarefa parada

Status: Doing · Estimate: 8 · Remaining: 0 · Blocker: dependência externa sem resposta · Review: ainda não iniciada.

A implementação terminou, mas o bloqueio impede a entrada em Review. Investigue o motivo, escale a dependência quando a ação estiver disponível e, após o desbloqueio, acompanhe o fluxo para Review e QA.
